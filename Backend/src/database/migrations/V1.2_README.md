# Version 1.2: reportes, evidencia y limite de Creel

Los scripts de DOG-30 son:

- `V1.2__crear_reportes_ubicacion_evidencia.sql`
- `U1.2__revertir_reportes_ubicacion_evidencia.sql`

La version 1.2 crea las siguientes tablas sin modificar las tablas heredadas de
las versiones anteriores. La version 1.3 normaliza sus nombres finales a
minusculas para que sean portables entre MySQL local y Cloud SQL:

- `reportes`: reporte anonimo o asociado a un usuario, caracteristicas del
  avistamiento, coordenadas exactas privadas y estado de moderacion.
- `evidencias_reportes`: fotografia opcional, MIME, tamano, SHA-256 y resultado
  de la comprobacion de metadatos. Solo admite una fotografia por reporte.
- `poligonos_creel`: versiones del GeoJSON aprobado para validar territorialmente
  un reporte.

Los scripts complementarios de normalizacion y limpieza son:

- `V1.3__normalizar_nombres_tablas_nuevas.sql`
- `U1.3__revertir_nombres_tablas_nuevas.sql`

`V1.3` redirige `Bitacora_Administrativa` de `Registros` hacia
`reportes` y elimina las tablas heredadas vacias `Fotos` y `Registros`.
`Usuarios` se conserva sin cambios. Si MySQL ya almaceno las tres tablas
nuevas en minusculas, la parte de normalizacion de nombres no realiza cambios.

## Aplicacion manual en desarrollo

1. Confirmar que la conexion seleccionada en DBeaver corresponde a `dogalert`.
2. Respaldar o usar una base de desarrollo desechable.
3. Confirmar con `COUNT(*)` que `Registros`, `Fotos` y
   `Bitacora_Administrativa` no contienen filas.
4. Ejecutar completo `V1.2__crear_reportes_ubicacion_evidencia.sql`.
5. Ejecutar completo `V1.3__normalizar_nombres_tablas_nuevas.sql`.
6. Verificar las tablas con `SHOW TABLES;` y `SHOW CREATE TABLE`.
7. Ejecutar pruebas de insercion, anonimato, unicidad y borrado en cascada.
8. Adjuntar la evidencia a DOG-30 antes de solicitar el merge.

`U1.3` recrea la estructura de `Registros` y `Fotos`, pero no recupera
filas eliminadas. Para revertir todo en una base desechable se ejecuta primero
`U1.3` y despues `U1.2`. Ninguno debe ejecutarse en la instancia compartida
de Cloud SQL.

La geometria oficial de Creel no se inventa ni se incluye en el repositorio. El
registro de `poligonos_creel` se insertara cuando el equipo reciba el GeoJSON
aprobado y pueda calcular su SHA-256.
