# Version 1.3: DOG-37 / HU-04, HU-05 y conservación

Esta migracion prepara el esquema Cloud SQL para DOG-37 y HU-05:

- Usuarios registra login/actividad, estado, fecha y marca de anonimización.
- Reportes almacena el hash SHA-256 del contenido usado al crear el reporte.
- `Clave_Idempotencia` deriva del UUID único del cliente; ambas claves tienen
  restricción única y no pueden divergir.
- Reportes conserva un indicador de eliminación lógica, fecha de solicitud y
  fecha mínima de conservación. El trigger impide el borrado físico anterior a
  cinco años de la creación.

## Aplicacion manual en desarrollo

1. Respaldar la base y comprobar que están aplicadas V1.0 y V1.2.
2. Ejecutar completo `V1.3__persistencia_offline_idempotencia_retencion.sql`.
3. Verificar índices, columnas y trigger con `SHOW CREATE TABLE Reportes;` y
   `SHOW TRIGGERS LIKE 'Reportes';`.
4. Probar inserción de UUID repetido, fechas de conservación y rechazo del
   borrado físico antes del vencimiento.
5. Ejecutar pruebas offline/online en build nativo y guardar resultados en
  DOG-37; la historia de administración de reportes es HU-05.

El borrado lógico de HU-05 debe retirar evidencia, ubicación y contenido
personal inmediatamente, conservando solo el UUID/hash técnico y el plazo de
retención. Las operaciones de edición, borrado lógico y anonimización deben ser
transaccionales y validar en servidor que el usuario autenticado es propietario.
La migración no sustituye esos endpoints.

`U1.3` elimina el trigger y los campos agregados. Es destructiva para los datos
de actividad, hashes y conservación generados después de aplicar V1.3; usarla
solo en bases desechables o tras una copia de seguridad.
